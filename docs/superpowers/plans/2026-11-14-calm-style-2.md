# Calm Style "차분하게 2" in the Existing App (Chat View, Phase 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the whole existing spawn app the approved calm look "차분하게 2" (tokens, quiet session view, 상세/간략 list with the session tab row removed, resizable left panel, one text-size control for UI and terminal, every other surface restyled), with no chat view yet.

**Architecture:** One new stylesheet `src/styles/tokens.css` holds every design value as CSS custom properties on `:root`; the four existing stylesheets are converted in place to read them (no component rewrite). Three small pure modules carry the new behaviour (`src/textSize.ts`, `src/sessionList.ts`, `src/sideWidth.ts`) and are unit-tested; the session tab row (`SessionTabs.tsx`) is deleted and its jobs move to the left list, a new list header and a new session header. A committed screenshot harness renders the real built UI with a fixture bridge so every task is compared with the design lab.

**Tech Stack:** React 18 + TypeScript + Vite, plain CSS, Electron (untouched apart from `status-card.html`), xterm.js (untouched), vitest (node environment: pure functions and source/CSS-text checks only), playwright-core from outside the repo for screenshots.

**Spec:** `docs/superpowers/specs/2026-11-13-chat-view-design.md` — sections "The look: 차분하게 2", the owner's specific decisions, Constraints, Phases (this plan is Phase 1 only). Source of truth for values: the design lab `~/Documents/spawn-site-lab/calm-lab/` (`tokens.css`, `app.css`, `views.css`, `app.js`, `views.js`, `index.html` drawer, `shots-v5\`). Most likely to bite a user, most likely first. Each has its check in the owning task.

3. **아주 크게 in a small window**: 1100×720, the left panel at 240px, and widget mode (340px wide): no horizontal scroll, nothing clipped or overlapping, the top bar still drops to icons. → Task 8 (shots `size-xlarge`, `widget-xlarge`, harness check `fit`).
4. **Close / rename / drag-reorder after the tab row is gone**, in 상세, 간략 and with the panel folded: × asks once then closes, the confirm state clears on mouse-leave, rename opens exactly one input, a drag still calls `terminals.move`. → Task 5 (harness flow `tabs-gone`).

### Decisions where the plan departs from the lab (all deliberate)

1. Left panel default width **300px** (the lab token says 280; the brief for this phase says 300). Range 240–420.
2. No pulsing dot on working sessions (nothing new animates).
3. The side panel's instruction box stays (the unified composer is Phase 3); it takes the look the lab gives it in widget mode.
4. The header keeps `padding-left: 18px` (lab: 16) so the ball stays 28px from the window edge, in line with the 56px rail; the Mac 78px rule is untouched. Other sections use the lab's 16px side padding.
5. The lab's bottom hint `.sess-foot` ("Ctrl+1–5 바로 가기") is not ported: in the app Ctrl+1–5 open views, not sessions.
6. Every neutral selection uses one value, `--sel-bg` (white 6 %); the lab varies between 6 and 8 %. The chosen session row is white 4 % plus the yellow bar.
7. Usage has two tones only: grey, amber from 80 %. Today's red above 90 % is dropped (the lab has none).
8. The text-size control shows on every view (the lab hides it outside the session view), because it sizes all of them.
9. The toast window and the status card do not follow the text step: they are fixed-size windows; they use the 보통 values.
10. Not in the lab, decided here by its principles: the update pill becomes a hairline button (ready = solid `--ink` on `--accent-ink` text); input focus borders become `--ink-3`; new controls get `:focus-visible { outline: 2px solid var(--ink-2); outline-offset: 1px }`.

## Visual verification (one method for the whole plan)

**Method:** `tests/visual/shots.mjs` renders the **real built UI** (`dist/`) in headless Chromium through playwright-core (loaded from outside the repo, so no dependency is added), with a fixture `window.spawn` bridge and a fixture WebSocket snapshot. The repo's own server runs as a child process only to serve `dist/` and the Pokémon pictures, with its own `SPAWN_HOME`, registry folder and port. No Electron, no pty, no real Claude session, nothing of the owner's is read.

Why this and not the isolated Electron instance of `spawn-promo\video-real`: that method needs a patched private copy of the app to move `userData`, real Claude sessions (slow, different every run) and a visible desktop; the session rows are drawn inline in `Widget.tsx`, so the QA page alone cannot show them. A fixture gives the same five sessions as the lab on every run, in normal mode, 업무 모드, the Mac class, every text step and both window sizes. What it cannot show — window drag regions, the real traffic lights, the toast window's real bounds, pty refits — is listed for the owner's test build in Task 15.

**Every UI task ends with these steps** (called "the visual steps" below):

1. `npx vite build`
2. `node tests/visual/shots.mjs --out "~/Documents/spawn-portfolio/_inbox/calm-2/<NN-task>/" --only <surfaces>` — after shots.
3. `node tests/visual/shots.mjs --sheet <surface> --out <same folder>` for each surface — writes `sheet-<surface>.png`: before (from `00-before`) | lab reference | after.
4. Open each sheet with the Read tool and check it against the task's checklist. A mismatch with the lab that is not in "Decisions where the plan departs" is a defect: fix it, or report it with the sheet.
5. Run the harness checks the task names (`--check fit|work`, `--flow …`); they exit non-zero on failure.
